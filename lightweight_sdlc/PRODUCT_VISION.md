## Decision Filter

Before adding or expanding a feature, ask:

- Does this support the product's north star?
- Does this make the product more useful without making it unnecessarily heavier?
- Does this fit the intended user experience?
- Does this preserve the user's safety, ownership, trust, and control?
- Can this be done simply enough to preserve the intended feel?

If the answer is not clearly yes, leave the idea in the backlog or parking lot rather than adding it to the core experience.

## Related Standards

This file defines product direction. `MVP.md` optionally defines the minimum release scope; `DESIGN_SYSTEM.md` defines concrete interface discipline; `CLEAN_CODE.md` defines coding discipline. When direction and discipline conflict, this file wins and the other documents must be reconciled.

**EXAMPLE ONLY:** Concise shape

- Product: a calm personal recipe book for home cooks preserving recipes and memories.
- North star: be the simplest trustworthy place to keep recipes and their stories.
- Trust: content belongs to the user, stays local by default, and is shared only through explicit action.
- Beliefs: simplicity over feature count; usefulness over novelty; control over automation.
- Experience: warm, readable, uncluttered, and based on familiar actions.
